# Расширенный эксперимент VisA

Протокол `visa-duration-v2`, 30 октября 2026 года. Цель — проверить,
как продолжение SSL меняет качество замороженных представлений относительно
необученного энкодера и ранних checkpoint, и зависит ли эта динамика от аугментации
и архитектуры. Исполняемый конфиг: `configs/visa/expanded.json`; v1 сохранён отдельно.

## Матрица

| Фактор | Значения |
|---|---|
| Категории | cashew, chewinggum, fryum, candle, capsules, pcb1 |
| Энкодеры | ResNet-18 и ViT-Tiny/16 архитектуры DeiT-Tiny, оба с нуля |
| SSL | SimCLR, VICReg, masked reconstruction |
| Аугментации | прежние; прежние + Rotate; прежние + CutPaste |
| SSL-seed | 6101, 6102, 6103 |
| Длительность | один продолжающийся запуск до 100 эпох |
| Оценочные эпохи | 0, 1, 2, 5, 10, 20, 30, 50, 75, 100 |

Итого **324 SSL-запуска**: 6 × 2 × 3 × 3 × 3. Дополнительно 36 уникальных
baseline эпохи 0: категория × архитектура × seed. Энкодер обучается отдельно для
каждой категории, как в v1; изображения разных категорий не объединяются в одном SSL.

Три seed означают три независимых обучения SSL: меняются начальные веса, порядок
batch, случайные аугментации и маски. Внутри одной архитектуры и seed начальное
состояние энкодера одинаково для всех методов и аугментаций, что проверяется хешем.
Разбиения и наборы объектов от SSL-seed не зависят. На каждом checkpoint заново
обучаются оба пробинга; отдельного перебора seed классификаторов не добавляем.
Сохраняем нынешнюю передачу seed в random_state классификаторов. Поэтому разброс
характеризует повтор всего протокола с новым SSL-seed, а не отдельно оценённую
дисперсию пробинга.

## Данные

Берём полный официальный train категории за вычетом прежних 20% validation.
Для трёх старых категорий сохраняем точные ID probe train, validation и test из
`manifests/visa/fixed.json`. Для новых применяем тот же алгоритм, split-seed
20261030 и официальный `2cls_highshot.csv`. Метки не передаются в SSL-loss.

| Категория | SSL / probe train N/A | Validation N/A | Test N/A | Доля аномалий SSL |
|---|---:|---:|---:|---:|
| cashew | 240 / 48 | 60 / 12 | 200 / 40 | 16.67% |
| chewinggum | 242 / 48 | 60 / 12 | 201 / 40 | 16.55% |
| fryum | 240 / 48 | 60 / 12 | 200 / 40 | 16.67% |
| candle | 480 / 48 | 120 / 12 | 400 / 40 | 9.09% |
| capsules | 289 / 48 | 72 / 12 | 241 / 40 | 14.24% |
| pcb1 | 482 / 48 | 120 / 12 | 402 / 40 | 9.06% |

Это **2261 уникальное изображение SSL** на шесть категорий. Для отдельного
энкодера доступно 288–530 изображений вместо 240; на старых категориях прирост
небольшой. Добавление категорий расширяет набор задач, но само по себе не увеличивает
обучающую выборку одного энкодера.

В основной сетке используем естественную долю аномалий каждой категории. Фактор
5%/20% из v1 здесь дополнительно не перемножаем: после validation доступны только
48 train-аномалий на категорию, поэтому при 20% предел — 240 уникальных изображений.
Повторение объектов не является добавлением новых данных. Сравнение v1 с полным
train v2 меняет и размер, и долю аномалий; его нельзя трактовать как изолированный
эффект размера выборки. Внутри v2 состав train фиксирован во всех условиях.

Число validation/test-аномалий остаётся 12/40 на категорию. Больше train и SSL-seed
не устраняют эту ограниченность оценки; сохраняем индивидуальные траектории seed,
recall, confusion matrix и AP рядом с precision.

## Три режима аугментаций

Базовый pipeline A0 полностью сохраняет v1:
RandomResizedCrop(224, scale=(0.395, 1.0), ratio=(3/4, 4/3),
BILINEAR, antialias=True), затем ColorJitter(.275, .275, .275, .1375), p=1.
После преобразований — RGB tensor и прежняя арифметическая нормировка ImageNet.

| Режим | Дополнение к A0 |
|---|---|
| A0 | Нет дополнительных преобразований |
| A1 Rotate | После crop/jitter равновероятный поворот на 0, 90, 180 или 270 градусов |
| A2 CutPaste | После crop/jitter перенос одного прямоугольного участка в другое место того же изображения, p=1 |

Rotate и CutPaste берём из [Appendix B статьи Yoo et al.](https://arxiv.org/pdf/2208.07734v7)
и [авторского кода SSL-AD](https://github.com/jaeminyoo/SSL-AD), commit
`0249fa7d6460dbbf1c5db29ef87c771a9b6a3a61`. Для CutPaste доля площади равномерна
в [0.02, 0.15]; aspect ratio выбирается с равными шансами из U(0.3, 1.0) и
U(1.0, 3.3), затем участок получает ColorJitter(.1, .1, .1, .1) перед вставкой.
Параметры применяются к изображению 224×224. Код авторов скачан в `external/SSL-AD`.

Композиции A0 + Rotate и A0 + CutPaste — наш экспериментальный дизайн. Статья
рассматривает другие SSL-задачи, в том числе создание псевдоаномалий, поэтому её
выводы нельзя автоматически переносить на положительные пары SimCLR/VICReg.
CutPaste может менять признак дефекта: этот режим проверяет эффект инвариантности
к искусственным локальным повреждениям, без предположения, что качество улучшится.

SimCLR и VICReg получают две независимые реализации одного выбранного режима.
Masked reconstruction получает одну аугментированную картинку, затем независимую
маску 16×16, ratio .75. Target — эта же картинка до маскирования, включая CutPaste,
а не исходник без аугментации: иначе дополнительно изменится задача восстановления.
Предобработка для пробинга и рангов остаётся детерминированной и общей для A0–A2.

## Второй энкодер и masked reconstruction

Предлагается `deit_tiny_patch16_224(pretrained=False)` без классификационной головы
и без distillation: patch 16, width 192, depth 12, 3 attention heads, согласно
[официальной реализации DeiT](https://github.com/facebookresearch/deit/blob/main/models.py).
Это компактный обычный ViT. Для признаков фиксируем среднее по patch-токенам после
последней LayerNorm, без CLS; такой же pooling используется при SSL и оценке.
Параметры pooling фиксируются до просмотра новых результатов.

Для ResNet сохраняются GAP и 512 признаков. Проекторы SimCLR/VICReg имеют общие
hidden/output 512/128; меняется только входная размерность 512 либо 192.

Чтобы сохранить одинаковый смысл masked reconstruction, оба энкодера получают
плотное изображение с нулями на скрытых нормированных пикселях. ViT обрабатывает все
patch-токены. Небольшой декодер ViT: Linear(192, 512), GELU, Linear(512, 16×16×3)
для каждого пространственного токена. У ResNet сохраняется декодер v1.
В обоих случаях loss — MSE только скрытых RGB-пикселей в [0,1], 147 из 196 патчей.
Это сравнение адаптаций masked reconstruction, а не точная реплика оригинальной
MAE с удалением скрытых токенов. Различия декодеров входят в различия реализаций.

Общий исходный режим: AdamW, lr=.001, weight_decay=.0001, batch 64, постоянный LR,
AMP при обучении, прежние коэффициенты SSL. Прежде чем запускать полную матрицу,
короткая техническая проверка ViT должна подтвердить градиенты, конечность loss,
воспроизводимость эпохи 0 и resume и измерить время с пробингом. Изменение optimizer
после такой проверки фиксируется новой версией конфига до основного запуска;
результаты test не используются для подбора.

## Оценка и сравнения

Сохраняются правила v1 из [VISA_PROTOCOL_RU.md](VISA_PROTOCOL_RU.md): замороженный
энкодер, новый LogisticRegression и LightGBM на каждом checkpoint, прежние сетки,
выбор гиперпараметров по validation AP и порога по validation precision при
validation recall ≥ .5. Основные графики — test precision аномалий и ROC-AUC,
рядом recall, F1 и AP; precision/recall/F1 нормального класса тоже сохраняются.

RankMe, CER, CovER и NESum считаются по прежним определениям для raw и L2-признаков
на фиксированных probe train, validation и test. Размерности ResNet и ViT различны;
абсолютные ранги интерпретируем внутри одной архитектуры и категории. На графиках
указываем N и D. Определения метрик не заменяем нормированными аналогами.

Для всех условий строим качество, loss и ранги по эпохам; качество против каждого
ранга; среднее ± sample SD и отдельные линии трёх seed. Дополнительно сохраняем
число optimizer steps: с полным train одна эпоха содержит 5–9 шагов вместо четырёх
в v1. Сравнения длительности делаются внутри одной конфигурации данных.

Заранее фиксируем парные разности для precision, ROC-AUC и AP: 100−0, 100−5,
100−10 и 100−30. Публикуем и отрицательные, и положительные изменения. Не выбираем
раннюю «лучшую» эпоху по test. Совместный рост ранга и падение качества описывает
наблюдаемую зависимость, но сам по себе не устанавливает причинность.

## Бюджет Kaggle

В v1 на одной T4 среднее время эпохи из 240 изображений было 8.79 с для SimCLR,
8.82 с для VICReg и 5.47 с для masked reconstruction; источник —
`reports/visa-duration-v1/loss.csv`. При batch 64 новый train даёт суммарно
39 batch на эпоху по шести категориям. Линейная экстраполяция времени на batch
для 162 запусков ResNet даёт примерно **28 часов работы сессии T4×2 только на SSL**:
`(8.79 + 8.82 + 5.47) / 4 × 39 × 3 aug × 3 seed × 100 / (2 × 3600)`.
Извлечение признаков, пробинг, запись и подготовка данных добавляются отдельно.

До замера ViT ориентир для всей сетки — **55–80 часов сессий T4×2**. Это грубая
плановая оценка при производительности ViT сопоставимого порядка, не обещание
времени завершения. Даже часть ResNet с оценкой близка к целой недельной квоте.

На проверке 30 октября API показывал 27.33 часа из 30 и время следующего сброса
31 октября 00:00 UTC (03:00 по Москве). Субботний сброс восстанавливает недельный
лимит; всю сетку не считаем одним ночным запуском или одной квотой.

Запускать по очереди: 36 baseline; технический замер ViT; основные задачи блоками
до 10 часов, включая резерв на завершение, с сохранением optimizer/scaler/RNG и переносом checkpoint в следующую
сессию. Каждый блок сохраняет результаты вне завершающейся сессии. Приоритет —
законченные тройки seed для A0 на обоих энкодерах, затем A1 и A2. Остановка по
лимиту времени не меняет целевые 100 эпох и не отбирает задачи по качеству test.
После первого блока уточняется бюджет по фактическому времени и расходу квоты.

## Реализация и запуск

Ветка `experiments/visa-duration-v2`. Манифест `manifests/visa-v2/fixed.json`
фиксирует 2261 SSL-изображение и 4709 изображений во всех разбиениях; исходные байты
каждого файла проверяются по `manifests/visa-v2/image_hashes.json` на Kaggle.
Код ViT берётся из timm 1.0.22, `pretrained=False`, dropout и stochastic depth равны
нулю. Fused attention отключён для воспроизводимости. ResNet v1 не изменяет
начальную инициализацию. Преобразования Rotate/CutPaste реализованы с указанными
выше параметрами, без загрузки или исполнения внешнего кода при обучении.

Сначала отдельный preflight: 36 baseline и по одной эпохе каждого метода на обоих
энкодерах (cashew, seed 6101, A0). Это начало обычных задач основной матрицы:
checkpoint переносится в следующий notebook, обучение продолжается с эпохи 2.
Preflight завершается ошибкой при пропущенных AMP updates или ошибке любого worker.

Затем две приватные сессии: по 162 задачи на ResNet и ViT, до 10 часов на сессию
с двумя GPU и одним worker на GPU. Исходники, конфиг и манифест включены в notebook
вместе с SHA-256. Обе сессии используют результаты preflight как входной источник.
Сохранение состояния и подготовка output получают резерв пяти минут в пределах
лимита сессии. При превышении 16 GiB output новые задачи останавливаются, активные
сохраняются на границе эпохи. Полные optimizer/model/scaler/RNG сохраняются для
незавершённых задач; у завершённых сохраняется final encoder без обучающей головы.

```bash
PYTHONPATH=src:.deps python -m pytest tests/test_visa.py tests/test_visa_expanded.py -q
python scripts/build_visa_expanded_kaggle.py --mode preflight --hours 1
kaggle kernels push -p kaggle/bundles/visa-ssl-v2-preflight --accelerator NvidiaTeslaT4

# После успешного preflight:
python scripts/build_visa_expanded_kaggle.py --mode resnet18 --hours 10 \
  --resume-kernel arinabazukina/visa-ssl-v2-preflight
python scripts/build_visa_expanded_kaggle.py --mode deit_tiny --hours 10 \
  --resume-kernel arinabazukina/visa-ssl-v2-preflight
kaggle kernels push -p kaggle/bundles/visa-ssl-v2-resnet18 --accelerator NvidiaTeslaT4
kaggle kernels push -p kaggle/bundles/visa-ssl-v2-deit-tiny --accelerator NvidiaTeslaT4
```

Для следующего блока использовать `--resume-kernel` предыдущего notebook и новый
`--slug`, чтобы не перезаписывать активную сессию. Конфиг и манифест при resume
должны совпадать побайтно по хешам; выполненные задачи повторно не обучаются.
`results/status.json` содержит полную очередь и её состояние, `analysis/` — CSV
качества, рангов, loss, baseline и парных изменений с раздельными architecture и
augmentation. Графики строятся после скачивания результатов, без расхода GPU-квоты:

```bash
PYTHONPATH=src python -m visa_ssl.analyze_expanded /path/to/results --plots
```

Необработанные эмбеддинги, predictions, модели пробинга и подробные метрики
сохраняются для каждого checkpoint. Метаданные `environment.json` и
`source_snapshot.json` фиксируют версии библиотек, GPU и точные исходники запуска.
