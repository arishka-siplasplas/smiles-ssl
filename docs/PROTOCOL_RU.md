# Протокол v1: SSL и аномалии

Дата подготовки: 2026-10-26. Статус: подготовка и техническая проверка;
длительные серии не выполнены. Параметры ниже — явные исходные решения
эксперимента, а не результат поиска лучшей конфигурации.

## Вопрос и заранее заданные сравнения

Проверяем, может ли продолжение SSL-претрейна ухудшать бинарную
классификацию аномалий. Основной показатель — Average Precision (AP),
дополнительный — ROC-AUC. Положительный класс всегда `1 = anomaly/defect`.
AP вычисляется через `sklearn.metrics.average_precision_score`, без
трапецеидальной аппроксимации PR-AUC.

Основной контраст для каждого датасета, метода и probe:
`ΔAP = AP(epoch 1000) − AP(epoch 100)`. Пары формируются внутри одного seed.
Отрицательное среднее с интервалом ниже нуля поддерживает гипотезу в данной
конфигурации. Положительное изменение и отсутствие убедительного изменения
также являются содержательными результатами. Не выбираем короткую эпоху,
датасет, probe или аугментацию по удачному результату test.

Пять seed моделей: **4101–4105**. Split фиксирован, seed **20261026**.
Парные 95% t-интервалы считаются по seed, а не по эпохам/объектам.
Это неопределённость обучения при данном split, не неопределённость по новым
выборкам. При пяти seed интервалы предварительные. Множество сравнений
не даёт общего подтверждения гипотезы одним значимым результатом; все
датасеты и оба probe должны быть показаны. Повторение на новых split —
отдельная подтверждающая серия, с новыми манифестами и конфигами.

Вторичный исследовательский анализ: связь изменений ранга и AP внутри seed;
рассматривать начальный рост и позднюю фазу отдельно. Корреляция всей
траектории не устанавливает причину ухудшения. Возврат к checkpoint с
максимумом validation допустим для отдельного сценария выбора модели,
но не заменяет основной контраст 100→1000.

## Данные и разбиение

Train/validation/test: целевые доли **60/20/20**; в каждой части оба класса.
Нормальные и аномальные объекты участвуют в SSL-train. Метки не передаются
в SSL loader и objective; probes получают только метки train при fit.
Validation используется для выбора гиперпараметров probes.

Точные дубликаты таблиц по всем входным признакам удерживаются в одной
части. Для каждой группы берётся преобладающий класс как stratum;
смешанные метки сохраняются, строки не удаляются. Внутри strata группы
перемешиваются фиксированным RNG, затем стабильно сортируются по размеру.
Первые три группы обеспечивают представительство train/validation/test;
остальные попадают в часть с максимальным дефицитом к целевому числу строк.
Из-за неделимости групп доли и prevalence могут немного отличаться.
Все исходные строки остаются ровно в одной части.

**MVTec AD: MODIFIED mixed-class protocol.** Для каждой из 15 категорий
отдельно объединяем исходные train и test, stratify по `good` и каждому
типу дефекта. Дубликаты определяются по декодированным RGB-пикселям.
Группы распределяются тем же алгоритмом. Если stratum содержит менее
трёх независимых групп, подготовка останавливается с явной ошибкой.
Манифест хранит путь, исходную часть, тип дефекта, бинарную метку, SHA256
файла и пикселей, split indices, фактические доли и распределение дефектов.
Перенесённые из исходного test в новый train пути перечислены отдельно и
не входят в новый test. Один encoder обучается на одной категории.
Маски локализации не используются. Результаты нельзя сравнивать напрямую
с официальным протоколом MVTec, где train состоит из нормальных изображений.

На всех методах/силах/seed используем одни и те же манифесты. Программа
проверяет хеш исходных данных при запуске. Тестовые объекты не используются
для вычисления средних, масштабов, доноров или SSL-loss.

## Энкодеры и головы

| Модальность | Энкодер и embedding | Инициализация | Reconstruction decoder |
|---|---|---|---|
| Таблицы | Linear(D,64)→GELU→Linear(64,64)→GELU→Linear(64,64)→GELU; 64D | Стандартная случайная PyTorch, общий seed | Linear(64,64)→GELU→Linear(64,D) |
| Изображения | torchvision ResNet-18, обычный stem, global average pooling; 512D, fc=Identity | `weights=None`, без ImageNet; общий seed | Linear(512,128×7×7), 5 блоков bilinear ×2 + Conv3×3: 128→128→64→32→16→3, GELU кроме последнего, sigmoid |

В пределах модальности архитектура и начальные веса энкодера идентичны
между методами. Декодер изображений получает тот же pooled embedding,
который оценивают probes; skip connections нет. Основной размер 224×224.
Изображения переводятся в RGB, bilinear resize полного изображения,
пиксели в [0,1]. Нет crop, flip и цветовых преобразований в базовой серии:
они могут удалить дефект или поменять ориентацию изделия. Resize может
ослабить очень мелкие дефекты; контроль разрешения — отдельный эксперимент.

SimCLR и VICReg: общая projector-архитектура `dim→128→GELU→64`, без
BatchNorm в projector. Probes всегда используют выход энкодера до projector.
BatchNorm самого ResNet-18 обучается только на SSL-train; во время извлечения
эмбеддингов действует `eval()`, статистики не пересчитываются.

SimCLR: две независимые аугментации, L2-нормирование projector-выходов,
NT-Xent с температурой 0.2, все 2B представлений, исключена диагональ,
единственная положительная пара — две версии одного объекта.

VICReg: `25×invariance + 25×variance + covariance`; invariance=MSE,
variance — средний по двум представлениям `relu(1−sqrt(var+1e−4))`,
выборочная variance/covariance с делителем B−1; covariance — сумма
квадратов внедиагональных элементов обеих covariance matrices / 64.

Masked reconstruction: восстановление чистого входа, MSE только на
выбранных координатах/пикселях. Видимые цели не дают loss. Энкодер получает
полный тензор с заменёнными значениями. Это адаптация принципа MAE к MLP/CNN,
не оригинальный ViT-MAE с удалением невидимых токенов. `mean`/`zero` —
masked reconstruction; `donor`/`noise` — явно обозначенные абляции
восстановления повреждённых значений, для noise — denoising.

## Аугментации

Каждый run использует одну семью и одну силу. Семьи не смешиваются.
Для таблиц случайно выбирается `round(p×D)` признаков на объект,
минимум один и максимум D−1; сохраняется реализованное число признаков.
При D=6 уровни p=.1/.3/.5 означают 1/2/3 признака, а не ровно 10/30/50%.

| Семья | Таблицы | Изображения |
|---|---|---|
| zero | Буквальный 0 в исходной системе координат NPZ, затем train-standardization | Чёрные патчи |
| mean | Среднее столбца train; после standardization равно 0 | RGB-среднее всех resized train-пикселей |
| donor | Значение того же столбца другой строки train; donor независим по координатам | Те же позиции патчей другого изображения train |
| noise | Gaussian N(0,σ²) в единицах train std, только eligible columns | Gaussian noise на пикселях выбранных патчей, clipping в [0,1] |

Для замены табличные уровни **p=.1/.3/.5**; для изображения патчи 16×16,
уровни **p=.25/.5/.75**. Для noise выбирается **30% eligible features**
таблицы при σ=.05/.15/.3, либо **50% патчей** изображения при σ=.02/.05/.1.
Маски независимы между объектами и двумя представлениями.
Ни один donor не совпадает с текущей строкой/изображением по индексу;
значения берутся исключительно из train. У таблиц сохраняются дубликаты,
поэтому другая строка иногда может иметь то же значение — это допустимо.

Eligibility noise определяется только по train: >20 уникальных значений,
ненулевая variance, не целочисленный столбец. Это операционное правило для
числовых признаков данных NPZ, не автоматическая проверка медицинского
смысла. Низкокардинальные/категориальные столбцы исключаются; список
индексов и статистики сохраняются в манифесте для проверки. Если доступна
семантическая схема, следует ужесточить список до подтверждённых
непрерывных признаков новым вариантом манифеста до основной noise-серии:
например, флагом `--noise-columns 1 2 3 4 6` у команды `prepare` для cardio
(индексы с нуля; команда принимает ограничение существующего списка).
Gaussian noise не гарантирует физически допустимые исходные значения;
интерпретировать его как математическое возмущение представления.

Вся стандартизация вычисляется только по train (population std, при нулевом
std scale=1). Для zero сохраняем `−mean/scale`, поэтому это не замена средним.
Если данные в источнике уже центрированы, варианты могут быть близки;
`zero_mean_replacement_distance` позволяет увидеть эту близость.

## Оптимизация и бюджет

AdamW, weight_decay=1e−4. LR=1e−3 для таблиц и 3e−4 для изображений;
batch=256/64 соответственно. 1000 эпох, warmup 10 эпох, затем cosine decay
на всём горизонте 1000 эпох. Нельзя сравнивать epoch 100 этого запуска с
отдельным 100-эпоховым запуском с другим cosine schedule как одинаковые
состояния обучения. Singleton последнего batch пропускается одинаково для
всех методов. Число объектов и шагов сохраняется для каждой эпохи.

Checkpoints: **0,1,2,5,10,20,50,100,200,400,600,800,1000**.
Epoch 0 — случайный энкодер, обязательный контроль.
SSL-loss записывается каждую эпоху со всеми компонентами VICReg.
Значения losses разных методов не имеют общей шкалы качества.
Равное число эпох не означает одинаковое время: reconstruction использует
один проход энкодера, другие методы — два; сохраняется wall time.

Основная серия фиксирует `mean`, p=.3 для таблиц / p=.5 для изображений:
270 запусков. Отдельная сетка четырёх семей × трёх сил — 3240 запусков
включая основную серию (2970 дополнительных). Пилоты по 20 эпох, seed 3101,
служат проверке сигнала, времени и памяти; параметры probes в них те же.
Не выбирать гиперпараметры по test. Изменения по итогам пилота требуют новой
версии протокола до основного обучения. Потенциальный контроль механизма:
постоянный LR вместо cosine; он не входит в текущую основную сетку.

## Probes и спектры

На каждом checkpoint извлекаем эмбеддинги **исходных объектов без
аугментаций** в eval/no_grad. Заново обучаем оба классификатора, без warm
start. Train и validation не объединяются после выбора гиперпараметров.

Логрег: scaler.fit только на train embeddings; L2, lbfgs,
C∈{.01,.1,1,10,100}, class_weight∈{None,balanced}, max_iter=10000.
Несходимость — ошибка, а не молчаливое использование модели.
CatBoost: CPU, 300 деревьев, learning_rate=.05, depth∈{4,6},
l2_leaf_reg∈{1,3}, веса {None,Balanced}, Logloss, без early stopping;
thread_count=1, фиксированный seed. Каждый кандидат fit только на train.
Если embedding полностью постоянен, CatBoost не может обучиться; для этого
вырожденного случая записывается prior-only predictor и явный флаг fallback.
AP равен prevalence, ROC-AUC=0.5; это сохраняет оценку при полном collapse.
Выбираем максимальный validation AP, ничьи разрешаем порядком сетки.
Сетки и бюджет неизменны для всех методов, эпох и исходных признаков.
Это сопоставимый подбор каждого probe, а не требование одинакового числа
кандидатов между логрегом и CatBoost.

Для таблиц оба probe также обучаются на исходных признаках с тем же split
и сеткой; стандартная train-нормализация — аффинное преобразование признаков,
не обученный embedding. Эти результаты показаны горизонтальной линией.

Спектры считаются отдельно на всех фиксированных train/validation объектах
в float64, на сырых encoder embeddings, до probe-scaler и без L2-нормировки.
Для центрированной матрицы Z с singular values s:

- eigenvalues λᵢ=sᵢ²/(N−1);
- **Covariance effective rank** `exp(−Σpᵢlog pᵢ)`, p=λ/Σλ — основной ранг;
- **Centered singular effective rank** — та же энтропия с p=s/Σs;
- participation ratio `(Σλ)²/Σλ²`;
- stable rank `Σλ/max λ`, top-1 variance share, total variance и mean norm.

Сохраняется полный covariance spectrum. Нулевой спектр: collapse=true,
ранги=null. Никакой подстановки epsilon в вероятность для энтропии.
Effective rank не смешивается с RankMe на нецентрированной матрице.
Ранги разных размерностей/разного N напрямую не сравниваем.

После фиксации конфигураций и завершения всей серии отдельная test-команда
применяет сохранённые probes ко всем заранее заданным checkpoints.
Таким образом доступны test-кривые без подбора по test. Команда технически
проверяет завершение конкретного run; фиксация всей серии — порядок работы
исследователя. `analyze` создаёт кривые AP/ROC-AUC/loss/спектральных метрик,
95% интервалы по seed, CSV и парные контрасты long−short. Категории MVTec
показываются отдельно; усреднение по объектам из разных категорий не
подменяет сравнение внутри категории.

## Воспроизводимость и границы проверки

Run хранит конфиг, неизменный manifest, снимок исходников, commit/dirty
status, версии Python/библиотек, device, encoder checkpoints, обученные
probes, embeddings, кандидатов hyperparameters, loss и RNG/optimizer state.
Генератор оценки не меняет поток случайности обучения. CPU resume проверен
на точное совпадение с непрерывным обучением. CUDA требует отдельного smoke
в целевой среде; побитовая одинаковость между устройствами не обещается.
MPS не входит в v1. Предусмотрено продолжение при неизменных коде и конфиге;
завершённые результаты не перезаписываются.
