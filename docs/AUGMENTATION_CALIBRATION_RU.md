# Подбор аугментаций для табличной классификации аномалий

Дата: 2026-10-29. Дополнение к основному протоколу. Задача — выбрать
умеренные настройки **по качеству обнаружения аномалий**, до длительных
SSL-запусков. Проверяем все четыре семьи: zero, mean, donor, noise.
Первоначальная сетка с долями .1/.3/.5 остаётся для воспроизведения v1;
для новой табличной серии используется процедура ниже.

## Что считать утечкой и где используются метки

| Операция | Статус в нашем эксперименте |
|---|---|
| Среднее/масштаб по всему смешанному train без обращения к y | Допустимо; наличие аномалий может менять статистику, но не передаёт метки |
| Донор случайно из всего train, независимо от классов исходного объекта и донора | Допустимо для SSL; может разрушать зависимости между признаками |
| Выбирать доноров только того же истинного класса, отдельное среднее или силу для нормальных/аномальных | Использование разметки в обучении энкодера; отдельный supervised/semi-supervised вариант |
| Использовать только известные нормальные строки как пул доноров или для среднего | Тоже использование train-меток, даже если это правило одинаково для всех получателей |
| Оценивать последствия одной общей аугментации отдельно по классам | Допустимо как диагностическая оценка; метки не меняют саму аугментацию |
| Выбирать одну общую силу по размеченному validation | Supervised model selection поверх SSL-претрейна; это нужно явно заявлять |
| Использовать test для выбора силы, donor pool, нормализации, отбраковки или остановки | Утечка из test; запрещено |

Train-метки в class-conditioned аугментации **не являются сами по себе
утечкой из test**, если split соблюдён. Но заявлять такой encoder как
обученный без меток было бы неверно. Нельзя сравнивать его с обычным SSL,
не обозначив дополнительную разметку. Основной вариант в этой ветке:
**class-blind SSL-претрейн + supervised downstream evaluation/selection**.

Результат каждого конкретного преобразования зависит от x и случайности,
но не от y. Пулы donor/mean смешанные, одно правило для обоих классов.
Распределения фактических изменений у двух классов могут различаться:
например, у аномалий координаты дальше от общего среднего. Это эффект
данных, а не скрытая ветка кода по классу.

Псевдометки или поиск близких доноров по x также меняют метод. Это не
утечка истинных меток само по себе, но возможны усиление ошибочных
псевдометок и сглаживание аномалий. В текущую основную серию это не входит.

## Две составляющие силы

Прежняя маска меняла минимум один признак на каждом объекте. При D=6 это
минимум 1/6≈16.7%, даже если запрошено p=.01. Поэтому она не подходит для
очень слабых воздействий.

Новый режим `mask_sampling=bernoulli`: каждая допустимая координата
выбирается независимо с вероятностью p, минимум изменённых координат
не навязывается. Ожидаемое число выбранных координат p×D, вероятность
не выбрать ни одной — (1−p)^D. При D=6 и p=.01 около 94.1% представлений
останутся без выбранных координат. При p=.1 — около 53.1%.
Доля фактически изменённых объектов может быть ещё меньше: выбранное
значение donor/mean/zero иногда уже совпадает с исходным.

Это уменьшение **частоты воздействия**, а не амплитуды отдельной замены.
Даже единственная замена важного признака может уничтожить аномалию.
Поэтому отдельно смотрим последствия только среди реально изменённых
объектов, чтобы множество неизменённых строк не скрывало риск.

| Семья | p | Дополнительная амплитуда |
|---|---|---|
| zero | .01, .025, .05, .1, .2 | Буквальная замена нулём в координатах NPZ |
| mean | .01, .025, .05, .1, .2 | Замена средним столбца из fit-части |
| donor | .01, .025, .05, .1, .2 | Замена значением того же столбца другой строки fit-части |
| noise | .05, .1 | σ=.01, .03, .1 в единицах fit std; только допустимые числовые признаки |

Итого **21 кандидат на датасет**. Для шума варьируются p и σ отдельно;
индекс pσ² используется только для порядка слабый→сильный, а не как
гарантия одинакового действия на все признаки. Промежуточное смешивание
значений с коэффициентом α не используется: такая операция уже отличалась
бы от буквальной замены и могла бы создавать дробные категории.

В SimCLR/VICReg возможны две одинаковые исходные версии объекта; это
ожидаемая часть слабого режима. Есть отдельный контроль p=0 для этих методов.
Для masked reconstruction p=0 не определяет целевой loss и не запускается.
При p>0 объекты без выбранных координат не дают reconstruction loss;
batch без единой цели пропускается, принудительная маска не добавляется.
Записываются реальные доли выбранных координат/объектов и число пропусков;
epoch reconstruction MSE взвешивается по числу скрытых целей.
При разных p число обучающих целей различается — одинаковые эпохи не
означают одинаковую статистическую эффективность.

## Этап A: дешёвая предварительная диагностика

Используется **только внешний train**. Внутри него строится 3-fold
StratifiedGroupKFold с seed 20261029; точные дубликаты не пересекают folds.
На каждой итерации:

1. По двум fit-folds вычисляются mean/std, eligibility для noise и donor pool.
2. На исходных fit-объектах и их метках обучаются два фиксированных
   диагностических классификатора: логрег C=1, balanced; CatBoost 300
   деревьев, depth=4, l2=3, LR=.05, Balanced. Подбора здесь нет.
3. Они оценивают исходные и аугментированные объекты третьего, audit-fold.
   Аугментация не получает его метки. Все источники замен — fit-folds.
4. Для каждого кандидата используются пять повторов случайной аугментации
   (7101–7105), с парными масками для сравнения уровней силы.

Записываются AP/ROC-AUC относительно **исходных меток**, изменение score
аномалий/нормальных, TPR/FPR, переходы через фиксированный порог и величина
возмущения. Порог каждого учителя фиксируется по его нормальным fit-объектам
с целевым FPR≤5%; фактический FPR на audit может отличаться и сохраняется.
Отдельно записываются переходы среди действительно изменённых объектов.

Это **прокси сохранения сигнала**: у нового объекта после аугментации нет
подтверждённой истинной метки. Ошибка учителя не доказывает, что аномалия
исчезла; совпадение прогноза не доказывает, что она сохранилась. Если
исходный диагностический классификатор слаб, его выводы особенно ненадёжны.

Предварительно фиксируем допуски, а не подгоняем их после просмотра:
падение AP >0.02, падение TPR >0.05 или рост FPR >0.02 (абсолютные доли).
Если у каждого из **двух** учителей превышен хотя бы один допуск, кандидат
`flagged`; только у одного — `review`; ни у одного — `not_flagged`.
Это эвристический фильтр бюджета, не статистический тест безопасности.
Повторы случайной аугментации не считаются независимыми выборками данных;
ложные доверительные интервалы по пяти повторам не строятся.

Из `not_flagged` берём самый слабый и самый сильный вариант каждой семьи.
Так сохраняется контраст силы при ограниченном числе SSL-запусков.
Если не проходит ни один вариант, семья автоматически не продвигается;
«наименее плохой» не объявляется подходящим. Все отклонённые варианты
остаются в отчёте. Результат `not_flagged` не означает «оптимальная сила».

## Этап B: выбор по настоящей downstream-задаче

Для короткого списка запускаются SimCLR, VICReg, masked reconstruction
на **всём внешнем train без меток в SSL**. Восстанавливаются mean/std и
donor pool уже из всего внешнего train. Внешний validation остаётся
исходным, без аугментаций.

100 эпох, seed моделей 3101/3102/3103; checkpoints 0/20/100.
LR schedule имеет горизонт 1000 эпох, чтобы первые 100 эпох соответствовали
началу будущей длинной серии, а не отдельному короткому cosine decay.
Сетки логрега/CatBoost те же, что в основном протоколе; на каждом checkpoint
они обучаются заново только на train embeddings.

До восьми кандидатов × 3 метода × 3 seed × 3 датасета = **216 SSL-пилотов**,
плюс 18 контролей p=0 (только SimCLR/VICReg). Это верхняя граница, не запуск
по умолчанию. Число уменьшается при отбраковке на этапе A.

Основной критерий выбора — AP на **чистом validation в epoch 100**,
усреднённый по трём seed, трём SSL-методам и двум probes. Для каждого
датасета и семьи выбирается одна общая сила для всех SSL-методов;
это сохраняет сопоставимость их последующего сравнения. Отдельные AP
обоих probes и все кандидаты остаются в отчёте. При отличии от лучшего
среднего AP не более .005 выбирается более слабая настройка.
Это условие близости, не утверждение о статистическом равенстве.
В `selection.json` отдельно сохраняется сравнение выбранного варианта с
контролями p=0 по каждому probe и SimCLR/VICReg. Падение более .02 AP
отмечается `review_before_long_runs`: сам выбор лучшего из кандидатов ещё
не означает, что аугментация лучше отсутствия аугментации. Генерация
длинных конфигов не запускает их автоматически.

Selector требует завершения всех запланированных пилотов и совпадения
конфигов/манифестов. Нельзя выбирать победителя по неполному удобному
подмножеству результатов. Семьи остаются отдельными экспериментами;
самая удачная семья не подменяет отчёт обо всех четырёх.

После выбора генерируются конфиги 1000 эпох на новых seed 4101–4105,
с сохранением основного контраста 100→1000. Сила не подбирается заново
для каждой эпохи: иначе эффект продолжительности смешается с изменением
аугментации. Test не открывается ни на A, ни на B. Чистый validation
используется для выбора настроек, поэтому его итоговая оценка оптимистична;
окончательное подтверждение проводится на отложенном test.

## Команды

Из корня репозитория после установки пакета:

```bash
smiles-ssl screen-augmentations --manifest manifests/adbench/cardio.json \
  --data-root data/adbench --spec configs/calibration/screen_v1.json \
  --output reports/calibration_new/cardio
# Повторить для mammography и annthyroid.

smiles-ssl plan-calibration \
  --screens reports/calibration_new/cardio/screen.json \
            reports/calibration_new/mammography/screen.json \
            reports/calibration_new/annthyroid/screen.json \
  --output plans/calibration_new

# Каждый полученный конфиг запускается обычной командой run:
smiles-ssl run \
  --config plans/calibration_new/table_cardio_simclr_mean_p0.01_s0_seed3101_bernoulli.json \
  --manifest manifests/adbench/cardio.json --data-root data/adbench \
  --output runs/calibration_new/cardio_simclr_mean_p001_s3101

# После завершения ВСЕХ запусков плана:
smiles-ssl select-augmentations --plan plans/calibration_new/plan.json \
  --runs runs/calibration_new --output plans/selected_long_runs
```

Файл `configs/calibration/screen_v1.json` фиксирует диагностические пороги
и seed. Его фактически использованная копия сохраняется внутри `screen.json`.
Старые fixed-count конфиги сохраняют прежнее поведение; run IDs новой
серии содержат `_bernoulli`, поэтому они не смешиваются с прежними.

## Методологические источники

[SCARF](https://arxiv.org/abs/2106.15147) использует случайное повреждение
признаков для табличного представления; это не гарантия сохранения
аномалий. [Class-conditioned augmentation](https://arxiv.org/abs/2404.17489)
явно рассматривается авторами в semi-supervised постановке.
Работа [Data Augmentation is a Hyperparameter](https://arxiv.org/abs/2208.07734)
обсуждает проблему выбора аугментаций для anomaly detection и оптимистичных
сравнений при неявном использовании меток. Наша двухэтапная процедура,
сетка и допуски — предлагаемый дизайн этого проекта, а не готовая
гарантия из указанных работ.
